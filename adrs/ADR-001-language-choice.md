# ADR-001 — Language and runtime choice: D with dub

## Status

Accepted

## Context

The ai-agent-subsystem is a Kubernetes operator that must be deployed as container images and run
inside cluster pods. Key constraints:

- The controller, supervisor, and initializer run in minimal container images (distroless or
  scratch-like); a language with a heavy runtime (JVM, Python interpreter, Node.js) requires
  shipping that runtime in every image, increasing attack surface and image size.
- The supervisor and initializer are injected into user-supplied Pod images. They must work across
  diverse glibc-based base images without installing additional dependencies.
- The team prioritised safety (memory safety, type safety), performance, and build reproducibility.
- A code-generation pipeline (`crdgen`, `tsgen`) needs to introspect the same struct definitions
  used at runtime — a single-language monorepo makes this natural.

## Decision

Use **D** (compiled with DMD for development/CI and LDC for production) as the sole language for
all runtime and tooling packages in the monorepo. Use **dub** as the build and dependency manager.
Produce **statically linked** binaries using LDC.

The one exception is `packages/agent-contracts`, a generated TypeScript npm package consumed by
users who manage Agents from Node.js applications; it is generated by `tsgen` from the D structs.

## Rationale

- **Static linking (LDC)**: No runtime dependencies. The supervisor and initializer drop into any
  glibc-based image without installing anything. Container images can be minimal.
- **D's safety features**: `@safe` functions, no implicit type coercions, built-in memory management
  via reference counting and GC — suitable for a long-running operator.
- **dub monorepo**: All packages share a single `dub.json` root. Sub-package references
  (`":agentcore"`) keep the build graph explicit. `make test` iterates over the list in one loop.
- **Code generation from the same model**: `crdgen` and `tsgen` introspect the same annotated
  D structs that agentcore uses at runtime. CRDs and TypeScript types cannot drift from the
  authoritative data model.
- **Build reproducibility**: The compiler version is pinned (`dmd-2.111.0` in CI) and declared in
  `dub.json` via `toolchainRequirements`. An unsupported compiler fails fast with a clear message.

## Consequences

- Developers need DMD or LDC installed. The CI workflow (`setup-dlang`) handles this automatically;
  local setup follows `CONTRIBUTING.md`.
- Bare `dub test` at the repo root is a no-op (root `targetType: none`). All test/build commands
  go through `make` or name a sub-package explicitly.
- The TypeScript contracts package requires Node.js 22 for its own tests, adding a second toolchain
  to the CI matrix — this is isolated to the `agent-contracts` job.
